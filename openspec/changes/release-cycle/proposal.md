## Why

Today TAI has no release pipeline. Pre-built binaries are not published anywhere, the only install method is a manual `go install` against the repo's main branch, and the plugin host's "latest plugin release" lookup talks to GitHub Releases that do not yet exist. The `pivot-to-ai-as-code` proposal explicitly deferred this work; the deferral note is the last open thread on that change.

This proposal turns that thread into a real, reproducible release cycle: pre-built binaries for `tai` and the Triage plugin attached to GitHub Releases, a Homebrew tap for non-Go-developer users, a `go install` path for Go developers, opt-in pre-releases for dogfooding, and a Makefile that lets a maintainer cut a release from their laptop with three commands. CI/CD is reserved for a follow-up — the first cut is intentionally local-first so the pipeline is debuggable end-to-end before any GitHub Action runs.

## What Changes

- **New tag scheme.** Core uses bare `vX.Y.Z` tags at the repo root (forced by Go's module-version rule — `github.com/dmastrorillo/tai/core/cmd/tai@latest` only resolves against root tags because there is one `go.mod` at the root). Plugins use prefixed tags `plugins/<name>/vX.Y.Z` (e.g. `plugins/triage/v0.5.0`). The two streams are independent and both ship from this repo from the same commits.
- **Two GoReleaser configs at repo root.** `.goreleaser.core.yaml` and `.goreleaser.triage.yaml`. Each uses GoReleaser's `monorepo.tag_prefix` to scope which tags it responds to. Each produces a separate GitHub Release page on its own tag. The triage archive is named `tai-plugin-triage-{{ .Os }}-{{ .Arch }}.tar.gz` to match `core/internal/plugins.AssetFilename` exactly — the plugin host's HTTP fetcher already expects this filename.
- **Cross-platform builds, no CGO.** Targets are `linux/darwin/windows × amd64/arm64`. `CGO_ENABLED=0` works today because `modernc.org/sqlite` is the only native-ish dependency and it's a pure-Go port.
- **Linker-injected versions.** Both configs set `-ldflags="-X github.com/dmastrorillo/tai/core/internal/version.String=..."` (core) and the equivalent for `plugins/triage/internal/version.String` (triage). The `version.String` vars already exist for this purpose.
- **Opt-in pre-releases.** GoReleaser auto-marks any tag with a SemVer pre-release suffix as `prerelease: true`. The banner and the plugin host's "latest" lookups skip pre-releases. Users opt in explicitly via `tai plugins <name> install --version vX.Y.Z-rc.N` or `go install ...@vX.Y.Z-rc.N` or by downloading directly from the GitHub Release page. The brew formula serves stable only.
- **Homebrew tap.** A self-hosted tap repo `dmastrorillo/homebrew-tap` (created empty as a one-time manual step). GoReleaser's `brews:` block on the core config writes and commits the updated formula to the tap on every core release. Install becomes `brew install dmastrorillo/tap/tai`. Plugins are explicitly NOT brew-distributable — see Impact below.
- **`go install` path for core only.** `go install github.com/dmastrorillo/tai/core/cmd/tai@latest`. The long path is the canonical Go-monorepo idiom (mirrors `gh`, `kubectl`). Plugins cannot be installed via `go install` because the plugin host discovers them by reading `<TAI_DATA_DIR>/plugins/<name>/<name>` — a binary in `$GOPATH/bin` is invisible.
- **Local-first trigger.** The maintainer runs `git tag <tag> && git push origin <tag> && goreleaser release --config <config> --clean` from their laptop. Required env: `GITHUB_TOKEN` (always) and `HOMEBREW_TAP_GITHUB_TOKEN` (PAT with write access to the tap repo, core releases only).
- **Makefile targets.** `make release-snapshot` (dry-run both configs with `--snapshot --clean --skip=publish,announce` to validate without publishing), `make release-core`, `make release-triage`.
- **Auto-generated changelogs, scope-filtered.** Each GoReleaser run auto-builds a changelog from git commits between its tag and the previous matching-prefix tag. Filter: include `feat`/`fix`/`perf` only. Core's changelog includes commits scoped `core` or `pkg` (pkg is shared framework code that ships in both binaries). Triage's includes `triage` or `pkg`. A `feat(pkg): ...` commit shows up in BOTH changelogs the next time each binary releases — this is real-world accurate, not a bug. Excluded: `openspec`, `ci`, `docs`, `chore`, `style`, `test`, `refactor`, `build` (not user-facing).
- **Re-enabled commit-lint CI.** `.github/workflows/commit-lint.yml` currently runs only on `workflow_dispatch` (disabled during the pivot). This change switches it to `on: pull_request` so the scope enum is enforced on every PR. The existing scope list (`core`, `pkg`, `triage`, `openspec`, `ci`) already covers everything in the release pipeline — no new scopes.
- **Banner + plugin-host fetch refactor.** Today `core/internal/sync/banner.go` and `core/internal/plugins/fetch.go` both call `GET /repos/{repo}/releases/latest`. That endpoint returns the chronologically newest non-prerelease release REGARDLESS of tag prefix. Under the new prefix scheme it can return a `vX.Y.Z` (core) release when the caller is asking "what's the latest triage release?". The fix: for any plugin-targeted "latest" lookup (banner's plugin rows + `tai plugins <name> install/update` without `--version`), switch to `GET /repos/{repo}/releases?per_page=100`, filter `tag_name` by the plugin's tag prefix (`plugins/<name>/`), drop `prerelease: true`, parse the suffix as semver, pick max. Core's "latest" lookup keeps using `/releases/latest` — works correctly because core tags carry no prefix and the endpoint already excludes prereleases.
- **CLAUDE.md amendment — independent-cadences framing.** The current text claims "core and each plugin ship on independent release lifecycles" (in the Conventions bullet on linker-injectable vars, and echoed in both `version/version.go` package comments). That overstates today's reality: first-party binaries in this repo share commits and ship together when convenient; the prefix scheme lets them release independently when needed; only THIRD-party plugins (in their own repos via `--source`) have truly independent lifecycles. The amendment retunes the language to match.
- **CLAUDE.md amendment — plugins-not-brew-distributable.** Add a one-paragraph constraint to the Plugin host section so a future contributor doesn't try to "helpfully" add a triage formula.
- **One-time manual step: create the tap repo.** `dmastrorillo/homebrew-tap` must exist (empty) before the first core release runs. Captured as an explicit tasks.md item so it isn't forgotten.

## Capabilities

### New Capabilities

- `release-cycle`: tag-scheme rules (bare for core, `plugins/<name>/` for plugins), GoReleaser config layout, archive naming conventions (asset filename pinned to the plugin-host fetch contract), linker-injected version strings, pre-release semantics (when surfaced, when skipped, how a user opts in), Homebrew tap shape and the brew-vs-plugin distribution boundary, `go install` paths, the local-first release trigger and required env, Makefile targets (`release-snapshot`, `release-core`, `release-triage`), changelog auto-generation with scope filtering, and the commitlint enforcement that makes the changelog filter reliable.

### Modified Capabilities

- `plugin-host`: the "latest plugin release" lookup behaviour changes. Today it uses `/releases/latest`. Under prefixed plugin tags it MUST instead list releases, filter by the plugin's `plugins/<name>/` tag prefix, drop `prerelease: true`, parse the suffix as semver, and pick max. The asset-filename contract (`tai-plugin-<name>-<os>-<arch>.tar.gz`) is unchanged but is now produced by GoReleaser rather than a hypothetical hand-rolled pipeline.
- `update-banner`: the plugin-row latest-tag lookups change identically — same list+filter+max-semver algorithm. The TAI core row keeps using `/releases/latest` (core tags carry no prefix). The banner's stable-only filtering becomes a documented invariant (today implicit in the `/releases/latest` behaviour; now explicit because the list endpoint exposes prereleases).

## Impact

- **New files at repo root.** `.goreleaser.core.yaml`, `.goreleaser.triage.yaml`. Both are checked in; `goreleaser` reads them on local invocation and (eventually) in CI.
- **Modified files.** `Makefile` gains three release targets. `.github/workflows/commit-lint.yml` switches its `on:` trigger from `workflow_dispatch` to `pull_request`. `CLAUDE.md` updates the conventions bullet on linker-injectable vars + adds the brew constraint to Plugin host. The two `internal/version/version.go` package comments lose their "independent release lifecycles" line.
- **Refactored code.** `core/internal/sync/banner.go` and `core/internal/plugins/fetch.go` gain a shared (or per-package) "list-and-filter latest by prefix" helper for plugin-targeted lookups. Existing `/releases/latest` calls stay for the core lookup path. The HTTP-mock test seams (`LatestTagForTesting`, `HTTPFetcher.GitHubBaseURL`) cover this without new test infrastructure.
- **New BDD coverage.**
  - `core/test-cases.md` gains a new `REL` category covering both the plugin fetcher's prefix-aware lookup algorithm (TC-REL-002..005: prefix filtering, prerelease exclusion, max-semver selection, malformed-tag tolerance) and the banner plugin-row consequences (TC-REL-006..008). TC-REL-001 pins the GoReleaser asset-filename contract against `core/internal/plugins.AssetFilename`. Cases live in `core/test-cases.md` (not `pkg/test-cases.md`) because the implementation sits under `core/internal/plugins` and `core/internal/sync`; the `pkg/` framework is unchanged.
- **No breaking changes for users.** Today nothing is installed via brew or `go install` against published releases (there are none). The new install paths add capability without breaking existing flows.
- **Breaking change for one internal contract: tag naming.** Any future automation that assumes `/releases/latest` returns the latest TAI release MUST be updated — but no such automation exists outside the banner/fetch paths this proposal already refactors. Worth flagging because the constraint is implicit in the current code.
- **External dependency: the tap repo.** `dmastrorillo/homebrew-tap` is a separate GitHub repo that must exist before the first core release. The PAT for GoReleaser's `brews:` block needs to be generated and stored in the maintainer's local env (and later, a GitHub Actions secret). Both are one-time manual setup steps captured in tasks.md.
- **Documentation.** README gains an "Install" section with the three paths (brew, `go install`, direct binary). CONTRIBUTING.md gains a "Cutting a release" section pointing at the Makefile targets and explaining the tag convention. CONTEXT.md is NOT touched — release-cycle is implementation, not vocabulary.
- **Out of scope (DEFERRED, explicitly).**
  - GitHub Actions CI/CD release workflow (port the local flow once it's proven).
  - `tai-beta` brew formula or `release-channel: beta` config (until a user asks).
  - `.deb`/`.rpm` packages via GoReleaser's `nfpms:` block.
  - v1.0 SemVer compatibility promise.
  - Tag GPG signing (`tag.signed`) — adopt when anyone cares.
  - `homebrew/core` upstreaming — defer until notability bar is met.
